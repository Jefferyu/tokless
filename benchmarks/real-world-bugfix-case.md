# 真实工程实测案例：Tauri + React 桌面应用全仓 Bug 排查与修复 A/B 对比

> **实验目的**：脱离“单文件静态抽骨架”的实验室数字，在真实的跨语言桌面工程（Rust 后端 + TypeScript/React 前端）中，检验启用 `tokless` 前后在 **Bug 检出质量、修复准确度、真实账单 Token 消耗（含 Cache Read 滚雪球）、探索步数与耗时** 四个维度的真实表现。
>
> **实测版本背景说明（`v0.1.0` 基线）**：本报告中的这组 Tauri + Rust + React 省流 53.2% A/B 盲测数据完成于早期的 `v0.1.0` 版本（当时仅包含基础语法骨架提取与无行号盲读拦截），目前尚未针对新版本重跑完整长任务对照；随着后续版本加入剥离外部 MCP 空载底座税的净身角色（`inheritMcp: false`）与优化后的行号切片放行机制，当前版本的理论综合省流表现更强。

## 一、 实验设计（严格控制变量）

- **测试靶标项目**：某生产级 Tauri 2.0 + Rust + React/TypeScript 智能语音桌面应用（含音频流采集、多引擎 ASR 并发调度、Windows 全局底层钩子 `WH_KEYBOARD_LL`、LLM SSE 流式润色与多窗口状态同步）。
- **分支隔离方式**：基于同一 Git Commit (`3908815`) 创建两个完全独立的 Git Worktree：
  - **对照组（Baseline · 原生常规模式）**：分支 `bench/baseline`，不挂载 `tokless`，按 Antigravity 默认习惯自由探索、读取文件并修复 Bug。
  - **实验组（Tokless · 启用 `tokless` 省流套件）**：分支 `bench/tokless`，启用 `tokless` 协议（开局第 1 步先调 `tokless skeleton` / `repo-skeleton` 获取前后端 `[L起-L止]` 语法骨架地图，后续一律带 `StartLine`/`EndLine` 按行号精准读取，严禁无行号全量盲读 >200 行代码文件）。
- **执行模型**：两组均使用同一模型 `Gemini 4 Hydrogen (High)`，下发一模一样的任务指令（*“全面调查前后端源码中的真实逻辑 Bug、并发竞态、崩溃隐患与内存/监听泄漏，找出至少 3~5 个实质性 Bug 并完成代码修复与构建验证”*）。
- **数据采集方式**：直接由 `tokless audit compare`（兼容 `agy-audit compare`）解析两组子会话底层的 `transcript_full.jsonl` 原始账单日志。

## 三、 为什么在真实任务里能省下 53.8%（1,123 万）的 Cache Read Token？

很多人以为省 Token 只是省掉“读文件那一刻的几千个字”，但真实账单揭示了 Agent 循环中额度消耗的核心规律：

1. **开局一张骨架图，省掉前 30 步“盲人摸象”**：
   - **对照组（Baseline）**为了搞清项目结构，前 115 步里调用了大量 `read_file` 逐块翻阅几千行的 `lib.rs`、`hotkey.rs` 和 `App.tsx`，直到第 227 秒才开始改第一行代码；
   - **实验组（Tokless）**开局第 1 步直接用 `repo-skeleton` 一次性拿到 `src/` 和 `src-tauri/src/` 所有函数、结构体与 `[L起-L止]` 行号地图，一眼看到关键函数行号范围，直接按行号精准切入，第 81 步（196 秒）就开始动刀改代码。
2. **减少模型往返轮次（64 轮 → 42 轮）= 直接斩断滚雪球乘数**：
   - 在多轮工具调用中，`累计 Cache Read ≈ 平均上下文水位 × 模型调用轮数`。
   - 实验组不仅把每一步的上下文水位压低了 **26.5%**（峰值从 43.9 万降到 32.3 万），更重要的是因为目标行号清晰，**模型调用轮数从 64 次直接降到了 42 次（少跑了 22 轮往返）**。
   - **“更薄的上下文 × 更少的调用轮数”** 产生乘数效应，直接把滚雪球缓存消耗从 **2,086 万 Token 砍到了 963 万 Token**，单次任务净省 **1,138 万 Token**。
